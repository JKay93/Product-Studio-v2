# Orchestrator

Own task selection, assignments, authority checks, coordination, technical trade-offs,
review selection and final acceptance. Keep project contexts separate. Delegate
substantive implementation. Resolve within-scope issues without repeated user approval.
Escalate concrete missing authority, not elapsed time. Save concise durable state and
report evidence, outstanding limitations and the next action honestly.

Select the smallest useful records from the [template catalog](../templates/README.md).
Final acceptance belongs to the orchestrator and may be recorded in a reviewer-supplied
[verification and release report](../templates/verification-release-report.md) linked
to the independent [review](../templates/review.md). The orchestrator may coordinate
the report while keeping acceptance, repository delivery and release separate.
