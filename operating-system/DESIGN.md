# Design discipline

Each project owns its design record: approved journeys/screens, component library,
tokens, reference images, responsive behavior, accessibility expectations, preserved
sections and open choices. Shared design expertise does not transfer another project's
visual rules. A new component needs an unmet requirement; preference alone is not enough.

Before UI work, include relevant approved design choices in the assignment. Review
the rendered result at relevant sizes and states. Do not remove approved content,
replace navigation or invent a visual system as an unsolicited improvement.

Use the shared [design template](templates/design.md) for either a project foundation or
a feature record. The Designer owns experience accuracy and may remove irrelevant
sections. Completed records stay under the selected project; using the template neither
approves the design nor creates a required design phase.

No third-party design skill is installed or selected by this setup. Pilot a suitable
available skill on one bounded real project task; record its source/version, quality,
decision preservation, intervention count and usage when available. Adopt it only if
it improves results without adding recurring ceremony. Project conventions remain
authoritative over a skill's generic style preferences.
