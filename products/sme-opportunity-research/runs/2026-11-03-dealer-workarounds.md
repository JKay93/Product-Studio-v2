### Carousell: significant new lead

[Carousell's GitHub organization](https://github.com/carousell) links carousell.com and publishes [Sellee](https://github.com/carousell/sellee), an Apache2.0 local selling agent. README names Carousell and Facebook Marketplace, browser-driven listing/reply/negotiation and Telegram/Discord as operator controls. This proves an existing implementation candidate, not that external WhatsApp/Telegram enquiries or a Carousell sold update work in our deployment.

[Local guide](https://www.sellee.ai/local) specifically offers Carousell for SG. Requirements include Chrome, Node/Playwright, signed-in paid Claude Code or Anthropic API billing; Windows currently uses WSL/Docker. Computer must stay awake; account restriction risk is expressly acknowledged. No install/runtime/model billing was started. [Browser documentation](https://github.com/carousell/sellee/blob/master/docs/browser-layer.md) confirms a dedicated profile, DOM reads/browser actions and session-bearing internal JSON reads for conversation lists, with login/DOM/network failure handling. No internal endpoint was probed. No stealth, CAPTCHA or access-control bypass was attempted or proposed.

The [carousell.ai MCP](https://www.carousell.ai/mcp) is **not** a direct substitute for controlling existing carousell.sg listings: its page says it publishes on carousell.ai. Its [terms](https://www.carousell.ai/terms) claim Carousell Group affiliation and currently describe California payment/delivery scope. Do not call it an unrelated imitation. Local Sellee documentation says its carousell.ai rail is always enabled even while offering an SG connector; exact SG behavior and publication defaults must be checked before allowing any launch. Source presence does not establish that all account automation is permitted or reliable.

Carousell's [mark-sold instructions](https://support.carousell.com/hc/en-us/articles/115006245027-How-do-I-mark-my-listing-as-sold) describe the actual app/web confirmation action; [undo instructions](https://support.carousell.com/hc/en-us/articles/115006245087-How-do-I-undo-mark-as-sold-option-for-my-listings) say users cannot reverse sold themselves and must contact support. A later state-changing test must be explicit about the exact seller-owned listing and consequence. No fake watch or fabricated buyer transaction should be created for testing.

The [MyEasyMarket integration page](https://myeasymarket.my/en/integrations/carousell) is a useful negative check: its own table says guided/manual listing, stock and orders, chat unsupported, with a sold reminder linking to Carousell. Its “integration” is not evidence of automated write access; Malaysia-targeted availability does not establish SG support.

### Messaging routes that avoid forcing a new customer channel

[360dialog coexistence docs](https://docs.360dialog.com/docs/resources/phone-numbers/coexistence) describe keeping the existing WhatsApp Business app number with API messaging and message echoes. They also state subscription/fees, active-use requirements, eligibility limits for fresh numbers, and unsupported companion-device cases. Provider documentation inspected; Meta's linked primary onboarding page returned429 and was not independently read. Do not say every new account qualifies or all device/history behavior is identical. This can address “I need to keep my app/number”, not a universal bypass of WhatsApp setup.

[Telegram connected business bots](https://core.telegram.org/api/bots/connected-business-bots) explicitly support processing/replying for an existing account, scoped recipients/rights and one connected business bot. [Bot API](https://core.telegram.org/bots/api#businessbotrights) limits can_reply to private chats with incoming messages in the last24hours. Arbitrary old history is not supplied by this webhook route. The official [client API](https://core.telegram.org/api/obtaining_api_id) provides a separate authorized-user-client option with its own API id and account login; it is broader session access, not an unauthenticated bot workaround.

[whatsapp-web.js](https://github.com/wwebjs/whatsapp-web.js) uses a browser/internal functions and expressly disclaims official affiliation and blocking guarantees. [Baileys](https://github.com/WhiskeySockets/Baileys) uses WebSockets/linked devices and also disclaims official affiliation. No libraries installed or sessions linked. Their existence disproves “technically no access” but does not establish a dependable/permitted commercial integration. No human-mimicking pacing or anti-detection settings were executed or recommended.
