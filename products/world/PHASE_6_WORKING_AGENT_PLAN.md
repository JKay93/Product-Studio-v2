## Tasks and completion [world:phase6-plan:tasks]
- world:task:phase6-provider-chat — server-only replaceable Anthropic adapter, bounded streamed replies, saved turns/history, useful missing-key/error/cancel/retry states. Use current supported API/model verified from official documentation and account availability; no SDK/provider secrets in client code.
- world:task:phase6-context-sources — effective permitted Agent instructions, recent Session messages and bounded relevant reference passages. Personal private content does not enter organization work by default or leak through borrowed Agents. Responses provide clickable exact sources through the existing reader; documents are untrusted context, never authority.
- world:task:phase6-meeting-work — pasted meeting notes produce proposed editable/assigned actions; user approves the exact revision; approved internal tasks and follow-up drafts persist in Work. Editing invalidates stale approval. No external sending, recording or real sub-agent delegation.
- world:task:phase6-durable-execution — shared Node worker/approved pg-boss, durable stages/retry/cancel/resume, idempotent effects, bounded attempts/time/output and current authority checks before provider dispatch and final effects. Runtime credentials must be narrow; privileged test/migration database configuration never becomes an application/worker fallback.
- world:task:phase6-proof — deterministic fake-provider unit/integration failure/recovery/approval/privacy/race/spend checks first, then a small root-controlled real-Claude fixture set below budget, browser/reopen/source/workflow proof and independent review.
- world:task:phase6-delivery — update stable canonical decisions/run/roadmap, scoped accepted app and Studio commits/pushes with remote verification; keep local web/worker available for testing.

Acceptance: a user chats with their persistent Agent, consults allowed sources, pastes synthetic meeting notes, edits/assigns/approves the proposed actions, gets saved internal tasks and an editable follow-up draft, then reopens the same work. Cancel/fail/restart/retry do not duplicate effects. Scope switches discard stale UI responses; revoked access blocks new context, dispatch and late result/effect publication. Changing proposals invalidates approval. Private credentials/content stay out of other Worlds, logs and browser bundles. Spend reservation prevents concurrent/retried calls exceeding the cumulative ceiling; uncertain charges stay reserved. Test/build/browser proof and independent actual-candidate review precede acceptance.
