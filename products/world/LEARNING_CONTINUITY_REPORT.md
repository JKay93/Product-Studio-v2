## Learning ownership and decisions [world:req:learning-ownership]

Ordinary work can propose a lesson without adopting it. Suggest is the default; Off disables inferred suggestions. The normal answer and an optional bounded learning annotation come from the same generation, avoiding a separate extractor call after every message. Only a deliberate authorized decision activates inferred learning. Explicitly authored memory is a separate human action.

Personal lessons stay private to their owner. Lessons derived from organizational work stay with that World even if phrased as preferences. A shared working preference is an exact selected-text projection to a named World; it exposes neither the rest of the personal store nor its private evidence. World policy can disallow projections. Borrowing an Agent grants no private-memory access.

World publication and portability are distinct. An eligible World owner/admin must currently have access to the originating evidence before publishing selected text to that World or releasing selected text to a designated recipient. A portable release requires separate exact-version recipient acceptance while membership remains valid. The accepted personal record contains the released text and safe provenance, without opening the internal source. Acceptance can happen repeatedly during employment, independently of leaving.

## Lifecycle and runtime boundaries [world:req:learning-runtime]

Memory has stable identity, immutable text versions and suggested/active/dismissed/retired states. Correction adds a version; Stop using prevents future admission and stale dependent execution while preserving authorized history. Neither action claims physical deletion or recall of prompts already transmitted to the provider. Exact decisions and retries are idempotent; cached notices and old versions never act as authority.

The existing context compiler admits a small bounded set of current authorized lessons. Session choices narrow eligible memory and learning; selecting a memory ID grants no access. Memory remains working guidance, not permission to grant tools, waive approvals, raise budgets or change platform rules. Universe, World, Agent-owner and Session restrictions remain enforced by the existing code paths.

| Layer | Responsibility in this implementation | Enforced boundary |
| --- | --- | --- |
| Universe | Closed `memory-v1` commands, validation, identity, immutable receipts/history, current checks, execution and spending fences | Neither model output nor remembered text can grant access or bypass executable approval/action checks. |
| World | Organization-owned candidates and lessons, selected World publication, named preference admission, exact release and safe departure | Organization work stays World-scoped; restricted evidence remains private until an authorized release of selected text. |
| Agent / owner | Personal learning mode, deliberate entries and decisions, correction/retirement and selected working preference sharing | Private owner content/configuration is unavailable in borrowed or organizational execution. Sharing an identity does not share its store. |
| Session | Current task/resources, optional exact memory selection and inference participation | `null` permits current eligible memory; `[]` admits none. IDs narrow existing authority; they do not grant it or permanently adopt lessons. |

The new executable command vocabulary is settings, session-settings, author, adopt, dismiss, correct, retire, publish, share, stop-sharing, release, accept and revoke-release. Read/history and departure preview/leave reuse the authenticated API. Commands carry exact versions/revisions and request IDs. Memory text is limited to 1,000 characters and Session selections to 100 IDs. No Knowledge-file write, external message, arbitrary code or new tool action was added; existing internal-task approval still governs effects.

At execution, at most five current memories are admitted, each at most 1,000 characters, within an 8,000-character serialized-memory ceiling and the existing total input/output budgets. Preferences are eligible by scope; factual/workflow entries use a simple keyword match. There is no new embedding service or per-Agent infrastructure. Same-generation annotation proposes at most two lessons; server code supplies actual source, job, owner and contributor provenance. Optional malformed annotations do not turn a valid ordinary answer into a mandatory learning failure.

Dependencies bind exact admitted versions, projections and source authority to jobs. Roots, delegated contributors, retries, aggregation and effects recheck current authority. A completed lawful result retains its existing historical access rules. Changing an ordinary preference does not itself rewrite completed conversations.

The first context binds Knowledge revisions, including an empty source list. Archive/restore changes authority even when a document version ID is unchanged, so it cannot revive an old job or pending learning decision. Source/contributor checks use a globally ordered lock set and reject dependency closures above 100 exact version/reviewer contexts; they never silently check only the first portion. A shared projection's private evidence is checked as its owner, while a colleague receives only the exact selected text. Current checks stay strict for new work/retry/effects, separate from already completed lawful history.

## User controls and departure [world:req:learning-controls]

Reuse Agent settings Memory, existing Settings/Permissions, Notifications and shared dialogs. Suggested learning appears through a quiet nonblocking notice and persisted review items. Authorized users can Adopt, Edit or Dismiss, inspect history, correct or stop use. Private management remains hidden for unowned Agents. Shared projections and portable releases expose only authorized selected text.

The ordinary journey is: complete useful work → persisted inactive suggestion → review in the nonblocking notice or Notifications → Adopt/Edit/Dismiss → fresh authorized Session admits the approved exact version. Agent settings → Memory provides ongoing inspection and history. Settings/Permissions provides World controls and departure. Learning Off stops inference, not existing approved memory; Stop using retires a particular entry. Notifications reuse five-second scoped polling rather than introducing a push service. The existing job-details view shows that node's exact Memory used; contributor dependency enforcement is complete, but the root inspector does not yet flatten all descendant memory into a single UI list.

Departure preview distinguishes pending work, pending releases and accepted continuity. Member self-leaving and authorized administrative removal use a guarded idempotent command; a World must retain an active owner. Leaving stops affected access, participation, pending work and unaccepted releases. Accepted personal lessons remain; organization records remain with existing authorized reviewers. Leaving one World grants no access to another and does not erase personal continuity.
