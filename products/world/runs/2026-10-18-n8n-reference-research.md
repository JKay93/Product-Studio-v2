## Findings and proposed World adaptations

1. Small typed blocks: Trigger, Action, Condition, Wait, Approval and Agent task, followed by controlled reusable subflows. Use named business fields and required input/output contracts rather than exposing raw expressions by default. Validate currency, quantities and exact accepted quote versions. Sources: https://docs.n8n.io/build/flow-logic.md and https://blog.n8n.io/data-mapping-best-practices/ .
2. Persist business progress separately from finite Agent jobs. n8n long waits store execution data and resume on a timer, webhook or form; waits below65seconds can stay in-process. World would persist customer acceptance/vendor confirmation/delivery waits with expiry, cancellation and authenticated correlated resume. No continuously running/polling LLM. Source: https://docs.n8n.io/integrations/builtin/core-nodes/n8n-nodes-base.wait .
3. Separate draft edits from published definitions. n8n production uses a published version; some settings changes automatically republish. World should require explicit activation for consequential changes and pin each active order to a version unless deliberately migrated, while rechecking current permissions and connector authority. Named/full history features have n8n plan limits; do not imply all are free. Source: https://docs.n8n.io/build/understand-workflows/save-and-publish-workflows.md .
4. Test mode with synthetic examples and simulated effects by default. n8n pinning/mock data is development-only and production ignores pins; pinning alone does not prevent other live nodes from external effects. World needs explicit test/live separation, not merely substituted trigger data. Source: https://docs.n8n.io/build/work-with-data/pin-and-mock-data.md .
5. Order-centred execution history: completed/waiting/failed step, input/output, attempt, provider receipt and next action. Debug/retry with saved data is useful, but neither retries nor a queue guarantee exactly-once external delivery. Reconcile uncertain sends and prevent duplicate order/invoice effects. Sources: https://docs.n8n.io/build/understand-workflows/understand-executions.md and https://docs.n8n.io/build/flow-logic/handle-errors-gracefully.md .
6. Customer quote acceptance is a business event; staff approval of a tool's exact parameters is a separate authorisation event. n8n can gate selected AI tools, not only all output. World should reuse existing scoped approvals without asking permission for every deterministic step. Source: https://docs.n8n.io/build/integrate-ai/ai-examples/human-in-the-loop-for-tools.md .
7. Agent-assisted building is already a documented n8n capability, not a unique World invention. World should let existing owned Agents draft/edit/explain disabled flows, then validate connections, fields, costs and permissions before enablement; credentials must stay out of model prompts. Source: https://docs.n8n.io/build/ways-of-building-workflows/ai-workflow-builder.md .
8. Reusable vendor subflows can have typed inputs and explicit join/completion rules. Canvas position should not implicitly decide commercial processing order. n8n1.0+ branch execution is documented as sequential by canvas position; worker concurrency is distinct, so do not claim branches automatically run in parallel. Sources: https://docs.n8n.io/build/flow-logic/break-workflows-into-smaller-parts.md and https://docs.n8n.io/build/flow-logic/understand-execution-order.md .

Product proposal: Flows list and business-friendly step forms/order timelines first; canvas for building/inspection. One flow definition can have many independent order executions. A Flow's Agent task references an existing Agent/team; the flow canvas is not the Agent collaboration graph. Reuse World queue, identity, permissions, approvals and accounting, but add durable flow instances/steps/events, not another embedded runtime. Current document Routines do not yet provide external connector workflows. Start with enquiry→requirements→quote→wait acceptance→order→vendors→wait delivery→invoice and explicit exception outcomes. Defer arbitrary code execution, unrestricted cycles/nested subflows and a broad connector catalogue. Typed vendor iteration can follow the first end-to-end pilot.
