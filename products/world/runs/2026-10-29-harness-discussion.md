## Findings and proposal
- Historical Pi recommendation assumed old SQL authority/execution would remain; fresh rebuild changes that tradeoff. Previous real-library scripted zero-spend tests establish mechanics only, not reasoning, model quality, latency/cost or production crash semantics. Pi core and experimental Pi Durable are distinct; Pi Durable supports checkpointed tasks, replay declarations and atomic transcript/documents, currently one process per storage instance. https://earendil.com/posts/pi-durable/
- Technical /root/harness_architecture_discussion and PM /root/harness_product_discussion requested sol/medium/none on recorded routing. Root verified current routes/roles before followups; activation/cost unknown. Specialists read relevant project sources, no implementation/duplicate reports. Root verified cited primary docs independently and challenged two issues below.
- Mastra ordinary Agent provides native model/tool loop and streaming; memory configurable; native Workflows support typed steps and stored suspension/resumption. Framework capabilities do not establish World company permissions or model answer quality. https://mastra.ai/docs/agents/overview ; https://mastra.ai/docs/memory/overview ; https://mastra.ai/docs/workflows/suspend-and-resume
- Root challenged unnecessary session reimplementation: current AgentController already supplies isolated live sessions, thread settings, UI events and allow/deny/ask tool policies. Technical revised proposal to probe Controller alongside ordinary Agent. Its live arbitrary state, grants, pending approvals and active runs do not automatically survive process recreation; durable threads are distinct. Some channel adapters without approval controls automatically run tools without UI approval, so World must independently refuse required-approval actions lacking durable authorization. Current web-only app has no channel exposure. https://mastra.ai/docs/harness/agent-controller
- Ordinary Agent/native Workflows vs beta durable-agent wrapper are distinct decisions. Durable agents are labelled beta; recovery can reissue model/tool calls. Current durable-agent store fencing is not the same as native Workflow advisory leases, nor a guarantee of exactly-once external effects. World needs stable operation receipts, payload-bound approvals, current authority rechecks and reconciliation for unknown external outcomes. https://mastra.ai/docs/harness/durable-agents ; https://mastra.ai/docs/workflows/overview
- Proposed operating contract: platform hard boundaries > authorized company policy > task instructions; separate guidance from code-enforced capabilities/access/budget. Documents are sources until authorized as procedures/rules. Context separates permitted source excerpts/versions, conversation, durable task facts, preferences and policy; retrieve relevant material, preserve authoritative facts outside summaries. Serialize conversation turns and version mutations.
- Natural conversation stays conversational; requested preparation can proceed within permissions without invented start approval. Clarification resolves material uncertainty; structured questions/approvals use one typed event source, tied to task/revision/owner and closed on answer/cancel/expiry. Expiry never consents. Draft acceptance and protected-action authorization are distinct. Approved company procedures can preauthorize permitted routine operations; allow/deny/ask outcome rather than approve every step.
- Root challenged memory friction: explicit remember requests already authorize scoped personal memory; task facts persist in task automatically. Inferred cross-task memory should be visible/editable/forgettable, ask when sensitive or materially uncertain. Shared company-rule activation needs an authorized owner. Employees may choose another template unless approved policy locks one; material template ambiguity is clarification, not invented owner approval.
- Proposed implementation boundaries: RunContext trusted principal/world/policy/budget; permitted KnowledgeResult source/version; ActionProposal exact inputs/tool/version/destination; ExecutionResult success/failure/wait/unknown plus receipt/retry class; versioned JobState. Framework snapshots describe execution; application records determine authority/business facts. Server-derived company scope and checks before reads/writes/reopening/export. Saved region and language independent.
- First proof proposed: one assistant prepares a document from a real chosen supported company template, uses actual permitted sources, asks a focused material question, accepts edits and resumes correctly. No invoice/quotation vertical selected, no arbitrary Word/Excel-format fidelity promise; supported artifact formats require explicit implementation. No agent directory/graph/flow canvas, autonomous background goals or extra memory agents enabled by default.
