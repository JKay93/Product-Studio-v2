### Persistence and one-trial invariant

Use a dedicated durable isolated live-compatible foundation file and separate worker journal under an explicitly named trial directory. Keep its original approved trial identity across restart. A fresh schema version3 may extend the native tables with a persisted execution-profile/rate/authority binding and one-trial latch; version2 synthetic stores continue exact existing schema validation. Create version3 only on a newly created isolated empty store; do not upgrade existing original/candidate v2 stores. Opening a live store requires matching immutable profile digest. Existing schema3 reopens for history/reconciliation, never reinitializes cap/latch/commands.

Retain normalized table constraints/foreign keys and immutable contribution/snapshot triggers. Permit synthetic0 in the isolated live schema; company-development test funding remains test-labelled even though provider compute is real. Persist actual sponsor/project/payer, live allowance authority, rate source/date/digest and provider-reported usage; retain raw quantities separately from computed microUSD and invoice-confirmed expense. No “synthetic=true” workaround or zeroed cloned ledger. Known/unknown prior shared-provider exposure is checked independently of this local database.

Start transaction binds one `trialId` to one Session and consumes its unique latch, holds A207500+B210000 microUSD, rejects existing latch/new Session even if prior task costs less thanUS$0.42, and checks account exposure/frozen status. Identical owner command replay returns its receipt without a new task; conflicting command rejects. Restart never clears latch; a new World/file/worker process does not imply a new authorized trial. Supervisor launch uses one canonical trial store/profile identity and exclusive launch/reservation record outside disposable previews; duplicate launch fails closed. Root records that path before activation. Filesystem cloning is not a security boundary; the authorized local operator must not create a second canonical trial from the same authority. No absolute cross-machine financial-enforcement claim.

Canonical registry is `.stage21-live/authority.sqlite` under the app, using FULL/DELETE durability and fixed trial identity/profile digest/absolute resolved store path. Keep durable consumed state outside the trial store so deleting/recreating that store cannot reset authorization. Registry/store commits are not cross-database atomic: consume registry first, then commit matching Session/reservations; an interruption leaves the registry consumed/blocked, never deletes it to permit another attempt. Valid replays and history reopen reuse the same identity; they do not launch inference again. Keep the registry out of publication and never mutate original ledgers.

Settlements derive from pinned integer rates (1 input/5 output microUSD per token) rather than an arbitrary browser value. Live result must be `provider-reported` and match actual selected model/envelope/source/dependency/epoch; synthetic result rejects in live mode. Unsupported cache/tool/count classes, input beyond200000, output above cap, missing usage, conflicting receipt or exposure discrepancy retains conservative hold and freezes further admission. Reconciliation is operator/accounting evidence only, append-only and idempotent; it cannot submit late content, accept a note or cause inference.

For this bounded activation the live reconciliation endpoint may remain deliberately disabled: unresolved cost stays held, root records external provider/account evidence as a follow-up, and no automatic settlement/release is inferred from a cached late response. Such evidence can support a later reviewed append-only accounting operation; this specification does not claim that operation is implemented now. Cached-content denial and preserved holds are required regardless of endpoint availability.

### Exact request, deadline and revocation contract

Use the [real test plan](STAGE-21-REAL-TEST-PLAN.md)'s1842-byteLF/no-trailing-newline fixture SHA256 `04f8df7420e053cc16b18c66a1c6342801b8ecbae0917ce7c9930643e1beec77`; fixed instructions and snapshot model are part of final manifest. A gets only that saved note, B that note plus immutable actual A artifact after owner confirmation. A and B retain distinct work/participant/runtime/attempt identities. Exact serialized request/envelope and dependency digests remain visible and persisted.

Maximum one count+one inference per role, two inference/two count requests total. Count is part of the approved trial, not an extra standalone diagnostic. Public documentation check and runtime credential-presence validation precede authenticated count; no paid probe/model fallback/extra count retry. Keep input-count admission4000/6000, request16/24KiB, output1500/2000 tokens and12/16KiB, provider body128KiB,60s per provider request and one in-flight inference. No tools/cache/thinking/batch/fast/private memory/external research. Fixed HTTPS endpoints only, redirects/retries disabled, bounded UTF-8 stream reading and abort while reading.

Endpoint-specific request construction is mandatory. Messages sends `service_tier:'standard_only'` and `thinking:{type:'disabled'}` with pinned model/system/messages/output cap. Count_tokens sends exactly `{model,system,messages}` for this tool-free text fixture; do not derive it by accidentally retaining inference-only fields. [Messages API](https://platform.claude.com/docs/en/api/messages/create), [count API](https://platform.claude.com/docs/en/api/messages/count_tokens), [service tiers](https://platform.claude.com/docs/en/api/service-tiers).

**Model-specific geographic compatibility:** omit `inference_geo` from both requests. Official [data residency documentation](https://platform.claude.com/docs/en/manage-claude/data-residency) says4.5 and older models reject that parameter, including `global`, with400; it supports4.6 and later only. Legacy models retain standard pricing and are unaffected by the later geography premium. This slice keeps Haiku4.5, not a new model/route or fallback. Describe first-party standard legacy pricing; do not claim per-request geographic pinning for this snapshot. Non-global response metadata is still unsupported by this narrow receipt validator and retains a hold; a provider-paid failure never permits another inference.

Usage compatibility accepts only existing bounded input/output quantities and zero cache totals, plus the following documented optional metadata. Absent/null metadata is permitted by the official nullable response types; when an object is present require every listed counter exactly numeric0 and no other keys. Never add decomposition counters to `output_tokens`, its inclusive billing total. [Official response types](https://raw.githubusercontent.com/anthropics/anthropic-sdk-typescript/main/src/resources/messages/messages.ts).

The240-second absolute task deadline starts at owner Start and includes count, inference, human A inspection and B. Show remaining time at the checkpoint; owner must actually review/choose Continue. No automatic checkpoint, conversational approval substitute, timeout pause or reset/extension. If the human takes longer, expire and preserve A, block B and release B only with proof never dispatched. Completing a partial run after that needs a separately authorized changed timing/attempt decision; existingUS$0.42 does not authorize another call automatically.

World claim means possible dispatch and holds cost conservatively. Worker durably commits unique journal reservation before count and dispatch-intent before paid inference. After count, `ack`/permit must transactionally recheck Session status, current epoch/deadline, matching attempt digest, frozen/actual funding profile and scope; current `acknowledge` alone must be strengthened for live mode because its baseline reads a claimed attempt but does not prove continuing authority. Recheck permission immediately before actual send; stop and permit are ordered transactions. A narrow window after issued permit remains possible already-authorized dispatch; describe it honestly and best-effort abort rather than promising remote cancellation.

Supervisor propagates stop/deadline to worker AbortSignal and monitors only the selected bounded task, never unattended recurring work. B launch follows actual owner Continue and exact retained A hash, not an automatic timer. Private capability binding/epoch/action verification remains at machine gateway; worker cannot invoke owner acceptance/continue. Failure closes that attempt, marks possibly dispatched cost unknown and never repeats count/inference. Cached journal receipt can be resubmitted only for the same attempt/digest under valid current content authority; after expiry/restart/revocation it supports accounting reconciliation only. Reopen/history and human acceptance of retained proposals never revive runtime grants.

## Approach and dependencies

Root obtains actual sponsor/provider project and previous-exposure information directly from the user; Technical Specialist/builder must not invent it. Profile validator requires independent authorized provider project/account evidence or explicit reconciliation of shared oldUS$1 charges/holds; a new API key or display label alone proves neither. Preserve every historical ledger/reservation/uncertain state. Bind approved fresh allowance to that actual funding route and retain proof reference. Missing data blocks activation, not unaffected implementation/review.

Public official sources re-opened without authentication2026-10-02: [models](https://platform.claude.com/docs/en/models/overview) lists `claude-haiku-4-5-20251001`,200K context and retirement no sooner than2026-10-15; [pricing](https://platform.claude.com/docs/en/about-claude/pricing) lists standardUS$1/M input,US$5/M output; [counting](https://platform.claude.com/docs/en/build-with-claude/token-counting) is free and estimated. Capture the actual dated rate basis before later authenticated request; no account entitlement is claimed from public docs. Aggregate reserve `2×200000+3500×5=417500` microUSD remains below approved420000. Changes in model/route/rates/extra charges fail closed and require a revised bounded decision.

Secret loading belongs exclusively to runtime launch after review/funding checks. Do not ask for the key in chat. Load only the selected existing environment variable into runtime memory; never print environment/header/raw SDK exceptions or save provider secret into profile/journal/World/browser/log/evidence. The launcher must strip provider secret from owner server/UI process environments if supervising a separate runtime. A runtime closure adds provider authentication only to the fixed provider URLs and hides exceptions. Machine capability travels private IPC/stdin/memory, not browser, command line or source. Secrets canary tests cover serialized prompts, client bundles, HTTP errors/logs and database/journal.

Chosen sequence: additive code/fake integration checks→independent frozen-candidate review→manual a11y outcomes recorded→actual root funding binding/public-rate recheck→explicit isolated startup with credential presence/authenticated count inside one approved trial→owner Start/A→real owner checkpoint/B→human review/acceptance/history/accounting report. No original migration, global installation/settings, purchases/top-up or silent inherited personal funds. Rollback disables live composition, retains trial store/journal and held costs, and leaves original human/offline/configuration paths available; never delete/reset/restore over newer evidence.
