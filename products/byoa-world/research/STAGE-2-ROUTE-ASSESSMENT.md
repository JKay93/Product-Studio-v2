## Scope and limitations

Question: what is the smallest credible route for two genuine independently running participants in the accepted human World foundation, and what protocol/authority changes does it require?

Method/corpus: read-only inspection of current application source under `BYOA-World/src/`, relevant studio project records, official OpenAI and Anthropic pages opened on 2026-10-01, executable existence/PATH discovery only. No `.data/`, `.phase1/`, `.foundation/` content or credential files were read. Historical receipts are cited through project evidence records. No current login, version, quota or network inference test was run. Current application working source is the inspection candidate; this is not a new verified runtime candidate.

The user's current direction is complementary expertise and linked deliverables. Proposed example: A converts the saved planning note into a project brief; B uses that brief and complementary expertise to produce an action plan; the human reviews both and accepts a selected final plan. B is a contributor with its own deliverable, not only a reviewer. Product planner→technical architect and project planner→delivery specialist are possible role choices, not selected defaults. Specific task, roles, pair and acceptance UX remain proposals pending package approval. Studio worker model routing is unrelated to the provider/models of BYOA participants; studio agents do not become connected product participants automatically.

## Interfaces and behavior

### Ownership and public ports — proposed

| Owner | Public contract / dependency |
| --- | --- |
| `agents/connection` | Participant/operator declaration, runtime binding, capabilities, enroll/authenticate/revoke and safe status. New TypeScript foundation entry owns no provider calls. Machine requests resolve identities from credential verifiers. |
| `work/session` | `create/get/stop`, immutable resource snapshots, participant-specific grants, ordered work, attempts, receipts and scoped activity. Calls World/note public interfaces; exposes authorization and contribution-commit seam to review. |
| `collaboration/document-review` | Attributed brief/plan contributions, proposal revisions, owner feedback/editing, acceptance receipt. Calls Session authority through public port and note/acceptance storage port; no provider logic. |
| SQLite platform | Repository/transaction adapter for new rows and atomic acceptance; no business scheduling or provider knowledge. Composite transaction port is explicitly owned by review acceptance, not a general shared service dumping ground. |
| `app/foundation` | Thin owner/machine HTTP composition and UI integration. Existing React/TypeScript/Vite, Calm design system, Node and SQLite remain selected. |
| Separate `runtime-bridges/` package/folder | Owner launches two processes independently from World. Provider-specific invocation and local journals/config live here; it consumes only the versioned protocol, not internal World services. Final folder/interface naming is delegated after approval. |

No import cycles or deep cross-feature imports. Runtime adapters must not be loaded into World startup. Automated boundary checks extend the foundation check to prevent World → provider-invocation dependencies and imports across feature internals. Two participant processes may run on the same machine/account for this local proof; independence means distinct externally launched runtime lifecycles/connections/work receipts, not distinct human owners or guaranteed host containment.

### Proposed versioned protocol

Use new `protocolVersion: 2`; do not silently reinterpret legacy v1 messages. Outbound polling from an operator-side bridge to fixed loopback World is the minimal local transport. Remote HTTPS, account systems and internet ingress are deferred. Exact schemas reject unexpected fields, invalid UTF-8, excess payloads and unsupported required capabilities. Runtime-reported identity/model/version/usage is labeled declared/reported unless independently corroborated.

| Operation / data | Minimum contract |
| --- | --- |
| Owner pair | Owned `worldId`, Session and participant slot A/B; short-lived single-use enrollment secret; proposed 5-minute expiry bounded by Session expiry. Secret shown only to operator, never in logs/prompts. |
| Enroll/handshake | v2, enrollment secret, runtime instance ID and supported input/output, cancellation and usage capability set. Verifier binds generated connection ID to human local owner, World, Session and participant; returned World bearer expires by Session expiry, proposed maximum 15 minutes. Reject unsupported major version and required capabilities. |
| Claim/ack/status | Credential-derived connection identity; `worldId/sessionId/participantId/workId/attemptId/grantEpoch`, envelope digest, sequence/event ID. Claim returns only assigned work. Durable ack grants one execution for that attempt. Duplicate ack never grants another invocation. |
| Work envelope | Purpose/role brief, permitted plain-text task/context, deadline, immutable `resourceId/revision/bodyHash` snapshot, prior contribution `id/revision/hash` when granted, allowed action/sharing table, resource limits and usage-report expectations. No executable/shell/config instruction or whole workspace from World. |
| Result/failure | Matching identity/epoch/digest, event ID/sequence, runtime run reference, bounded body, exact authorized source/dependency IDs/revisions/hashes, terminal outcome, optional reported usage/provenance. World assigns contribution ID and receipt only after transactional recheck. No body-supplied identity confers authority. |
| Stop/revoke | Immediate deny of future World disclosure and mutation; increment grant epoch, close leases and revoke credentials. Runtime cancellation request/ack is separate evidence; lack of ack remains unconfirmed. Already transmitted content cannot be recalled. |

Effective permission is the intersection of platform rules, World policy, agent/operator ceilings, Session grant and resource ceiling; any denial wins. A narrower Session grant cannot expand any outer ceiling. In this local slice outer policy is enforced allowlists/constants plus recorded operator declaration, not a full organization administration product. Grants include explicit recipients: A gets selected note snapshot; B gets selected note snapshot and A's committed brief if owner authorized A→B sharing. No access to a second World, unsaved edits, personal memory, unselected resources or other participant's journal.

Human owns create/start/stop, inspect, request changes, edit proposal and accept. Enrollment is Session-bound: the owner first creates a prepared Session with task, participant slots and frozen note snapshot, then pairs/enrolls A and B, inspects both disclosures, and explicitly starts when ready. Prepared Sessions offer no executable work. Participant owns claim/read assigned envelope, acknowledge, status and contribute only. Neither participant can enroll another slot, broaden context, start new work, write canonical note or accept. B's work is offered only after A has an authenticated committed contribution and current sharing authority; its envelope includes the human goal, the same frozen note snapshot, A's exact committed brief and B's role. No free-form generated text can schedule extra participants or invoke tools through World.

### Data, lifecycle and consistency

Persist connection bindings/verifiers and expiry; Session scope/purpose/status and grant epoch; immutable note snapshots; work/attempt identities/dispatch reservations; attributed contributions; proposals/revisions/feedback; acceptance receipts; safe metadata activity. Payloads are inspectable fictional/public work; audit lists IDs/actions/status rather than copying bodies or credentials. Define deletion/retention separately before private work. World/operator/provider each sees received payloads and may retain them; no private-readiness claim.

Session states: prepared → active (A, then B) → awaiting human review → accepted/ended; terminal failed/stopped/expired/indeterminate remain distinguishable. Connection connected/idle is not running. Work offered/acknowledged/running/committed/failed/indeterminate is separate from proposal accepted. Human can review saved artifacts after termination, without reviving grants. Reconnection with valid current credential can resend a cached result within live authority; revoked/expired/restarted Session requires a new explicit enrollment/Session and never reruns an old attempt automatically.

- Capture saved note revision and hash when creating the **prepared Session**, before enrollment or disclosure preview. Execution Start uses that exact frozen snapshot, with no implicit recapture. Later human save does not alter the prepared/authorized snapshot; show divergence. Deliberately selecting a newer note or changing task/source/sharing scope requires a new prepared scope and explicit pairing/authority confirmation, revokes previous credentials and advances the grant epoch before any new delivery. Old snapshot/work/attempt evidence remains preserved. Accepting a plan must compare the current note revision, not silently overwrite newer edits.
- A brief and B action plan remain distinct immutable Session contributions; B cites A's exact contribution ID/revision/hash. Proposal revisions are separate records; prior accepted note revisions and source linkage remain available.
- Offer/ack/reserve durably before inference. Runtime creates exclusive journal reservation before execution. A crash between ack and cached result is **indeterminate**; no new automatic inference. Transport retries resend the same attempt/event/body only. Conflicting replay rejects; identical replay returns existing receipt without new state.
- Transactionally recheck live Session, credential scope, epoch, deadline, exact snapshots/dependencies and work state at result commit. Stop racing result is ordered by the database transaction. After stop/revoke/expiry no late write succeeds. Separate read-only owner receipt lookup allows reconciliation without restoring agent grants.
- On World restart close all active grants/connections, increment epochs and mark unresolved work stopped/indeterminate; preserve contributions/proposals/receipts and note history. Runtime restart with reserved-only journal never retries inference. World cannot certify remote cancellation, provider erasure or undo external effects.
- Acceptance request includes owner command key, proposal ID/revision and expected canonical note revision. One SQLite transaction checks owner/World/proposal, saves selected final plan as the next note revision, records acceptance/source links and ends any active grants. Identical retry returns same receipt even after later note edits; same key/different payload rejects. Stale proposal/note rejects before mutation. Agent bearer always denied. Do not concatenate A/B blindly into canonical content.
- Proposed smallest revision behavior: one explicit owner edit/revision of the final proposal; it consumes no model attempt and requires fresh acceptance. Any request to rerun a participant is separate deliberate execution under remaining/new allowance, never an autonomous loop. If an agent-assisted revision is selected instead, specify which participant and its added attempt before approval.

## Approach and dependencies

### Suggested ceilings and accounting

Proposed local limits: two participant slots, one active Session per World, at most two initial runtime invocations (one A, one B), Session/bearer lifetime ≤15 minutes, invocation ≤60 seconds, bridge delivery lifecycle ≤120 seconds, each selected note/context snapshot ≤50,000 characters with independent aggregate UTF-8 envelope cap 256 KiB, contribution ≤20,000 characters with result request cap 128 KiB, bounded 128 KiB runtime event/output capture and 8 KiB sanitized stderr. If context exceeds envelope cap, fail before reservation and ask the owner to narrow it; do not silently truncate. Polling every second while awaiting work is bounded by bridge lifetime and server request/rate limits. These proposed numeric limits need package alignment; they are not evidence of token/cost containment.

World enforces World-request/attempt limits and rejects protocol excess. Bridge enforces local time/output/tool/config ceilings and must declare enforceable provider token/cost controls. Codex CLI event/output/time bounds do not establish a hard inference token/cost ceiling. Unknown token or subscription usage remains unknown; returned token figures are runtime-reported. Participant model/effort are operator-configured independently of studio aliases. The current [App Server examples](https://learn.chatgpt.com/docs/app-server) use `gpt-6.1-sol` but explicitly require signed-in account/workspace access; this does not select that model for BYOA. Preflight the chosen model/effort and record explicit requested settings separately from runtime-reported model/backend evidence; absent backend evidence remains unknown. Unsupported settings block the route; no silent model/provider/effort fallback. API paid routes require separate approval of model/token bound, maximum cumulative money and reservation method before any call. Default new external spending is **US$0**; do not charge against an old Claude allowance by assumption. Preserve original US$1 cumulative historical ledger, estimates, reservations, attempt IDs and unknown usage; a new stage/Session/chat never resets them.

### Rollout, migration and rollback

After approved Stage 2 package: (1) settle typed public contracts and offline protocol harness; (2) implement foundation enrollment/Session/storage and runtime-owned adapters; (3) integrate approved UI and review/acceptance; (4) independent candidate checks and meaningful fault scenarios; (5) only an explicitly approved bounded real demonstration. Do not execute prior weekly cycles. A fake harness is test-only, not a substitute participant in live proof.

Snapshot current foundation and preserve legacy stores/evidence before coding. Proposed migration v1→v2 adds participation tables and constraints in one SQLite transaction with explicit schema validation. Preserve original note/World/revision data and refuse unsupported/corrupt schema. No legacy JSON import. Test migration against copied stores and transaction failure. Old v1-only launcher will reject v2, so rollback means disable new routes using a v2-compatible human foundation while preserving records; restoring a pre-migration copy would lose newer writes and requires reconciliation/authority. Do not promise automatic downgrade. Final migration plan must be approved as part of the package, not smuggled into an adapter change.

Observability: record work/attempt/connection IDs, snapshot/delivery hashes, runtime run refs, phase, safe error category, cancellation acknowledgment and reported/unknown usage separately. Avoid raw stderr, environment dumps, bearer tokens and authentication outputs. A successful process exit alone is insufficient; require validated terminal event, bounded substantive result and World receipt. A live collaboration requires B's actual input capture/hash and contribution source links, not just labels that say “used A.”

## Verification and readiness

### Concrete Stage 2.1 preflight and bounded live plan — proposed, not authorized now

1. **Offline candidate review first.** Test two external processes with fake runtime calls; forging participant IDs, wrong World/Session/resource, expired/replayed enrollment, reused bearer, unsupported version, missing caps, byte excess, context tampering, A→B sharing denial, duplicate ack/result, conflicting replay and unauthorized acceptance must fail safely. Test stopped/expired/restarted authority, late result races, lost ack/result response, journal crash and persistence failure. Preserve note conflict/recovery and human-only regressions plus approved UI/keyboard/narrow-width/zoom behavior.
2. **Non-inference runtime preflight after package authority.** Operator resolves actual executable; capture sanitized version/help only and compare needed JSON/ephemeral/config/tool-disable flags and events with adapter support. Resolve the new Codex path rather than retaining absent pin. Check runtime-side authentication method locally without opening/copying credentials or exposing raw output; no login/import by World. Verify chosen model/effort support using permitted local capability/catalog evidence, recording request versus report and any unresolved entitlement; a catalog is not successful inference evidence. Separate A/B journal directories, connection IDs, fresh runtime contexts and operator-configured tools. Failed version/auth/capability/model preflight blocks only that route; no installation, privilege escalation, account changes or model/provider/effort/paid fallback inferred.
3. **User-approved live allowance required separately from design/code approval.** Proposed initial allowance: one new fictional/public A invocation, then one new B invocation only after A commits, ≤60 seconds each, no automatic inference retry, US$0 new external purchase/API spend using existing permitted subscription access. Record two durable new attempt reservations under Stage 2 identity while keeping every old consumed/indeterminate attempt. Existing unknown subscription usage is not zero. No fresh calls are made merely to see whether the route works.
4. **Execute dependency, then stop.** Independently launch/enroll A and B outside World; owner inspects each exact disclosure and authorizes; A creates brief; B receives exact committed A brief and makes action plan. Capture real runtime run/attempt/receipt IDs and B input dependency hash. If A fails/indeterminate, B does not execute; if B fails, show saved A partial work and truthful failure. Never relabel a synthetic response as B. Transport resend is same cached result, not another provider invocation.
5. **Human review/acceptance and closeout.** Show both immutable artifacts; human may edit the proposed final plan once and accept its exact revision, or leave it pending. Acceptance updates only the selected World's note, closes authority, survives restart/new Session, and rejects stale/duplicate-conflicting/agent acceptance. Platform walkthrough acceptance is distinct from accepting the plan. Evidence reports what actually ran and current quota/usage uncertainty; failed/unknown outcomes consume their reservations and trigger diagnosis/replan, never an unchanged retry.

## Implications and follow-up

The new stage can reuse proven lifecycle/deduplication ideas while preserving the accepted human foundation. The smallest proposed implementation adds two external scoped participants and a dependency-aware brief→plan Session, not a universal agent platform. Current path/version drift is a specific preflight dependency; historical successful runs remain useful but do not remove it. Two Codex bridges are the least additional route work; Codex+Claude remains a real alternative if its runtime, policy and budget dependencies are resolved. Neither recommendation commits the user to a provider pair.

Orchestrator reconciles this technical proposal with PM and Designer package, records user decisions once and delegates bounded Stage 2.1 work only afterward. Reviewer compares actual candidate and this memo's template mapping/authority invariants. No new code, model attempt, external spending or publication follows from this document.
