## Users and journeys

Keep the working sequence: World → Chat → explicitly selected offline task → contributions → human review → deliberate Knowledge save → reopened document and Activity links. Five surfaces, World switching, Chat default, actual saved configurations and direct specialists stay intact. No welcome hero, suggestions, attention panel or dashboard; PB-042 remains deferred. ### What is wrong in the actual candidate

The Knowledge screenshot shows raw rectangular selector buttons, a nearly full-width document with small monospace prose, large undifferentiated whitespace, stacked attribution paragraphs and adjacent ungrouped action buttons. The sidebar spends substantial height repeating the World identity and puts the World switch below navigation. The overall colour is correct, but composition reads as a collection of forms rather than one professional workspace.

The new Chat screenshot confirms the repair must change composition materially: a tall conversation-title button, an oversized bare textarea at the top, separated floating mention/send/save buttons and repeated Chat/New chat titles. Move the composer lower within a coherent thread; recolouring borders alone does not satisfy this repair.

Source explains the same pattern elsewhere: `ChatView` has two title levels and a 200px conversation column of ordinary buttons; all messages/tasks/setup/documents share the same generic boxed style. Generic `textarea` and `form` rules compete with component-specific layouts. Global CSS contains successive overrides, so spacing/font/edge treatments vary. Every prose output is a default `<pre>`, including saved documents and review confirmation. These are presentation failures, not a reason to change data/work contracts.

## Design system

### Shared shell and component rules

1. **Consolidate actual CSS.** Replace conflicting duplicated presentation declarations in `styles.css` and feature `chat.css` with explicit component rules; do not add another tail of unscoped overrides. Retain functional selectors, `[hidden]`, media/access rules and display semantics. Add named classes to existing markup where necessary; preserve React keys, handlers, ids, labels, controlled values and refs.
2. **Tokens.** Use only approved canvas `#F6F7FB`, white, ink `#202B45`, slate `#596579`, cobalt `#3454C5`, periwinkle `#E3E8FC`, apricot `#FBE6D4`, rail `#EEF0F7`, control edge `#788398` and divider `#DCE1EB`. System font explicitly: `ui-sans-serif, system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif`; remove unavailable Inter as an implied dependency. No font/image/network package.
3. **Typography.** Body 16px/1.65; page title 28–32px/1.2 weight700; section title20px/1.3; card title17px/1.35 weight600; secondary metadata13–14px/1.5. Reduce metadata weight and density, not legibility of decision-bearing copy. Use one margin rhythm: 8/12px within groups, 20/24px between components, 32px between sections. Long names wrap.
4. **Shell.** Desktop rail232–240px with 20px inset. Brand compact at top. Move the **existing guarded World select** to a context group above the five destinations; retain All Worlds and World details as clearly secondary links. Use existing World name once in the rail context rather than repeated owner/workspace paragraphs. Compact owner footer. Topbar64px minimum, white, 24–32px inset, World name plus one concise offline label; do not imply live availability. Content32px desktop/16px narrow, max1320px including list/inspector columns.
5. **Navigation.** Five 44–48px rows with existing SVG icons, 12px icon gap, 10px corners. Current row white with cobalt text plus solid accent/edge; no broad pastel nav slab or shadow. Normal rows have quiet hover only. Preserve `aria-current` and guarded navigation; changing a button's position must not bypass `navigate`.
6. **Controls.** 44px minimum height, 10px radius, clear primary cobalt/white action; white secondary controls use meaningful `#788398` boundaries. Quiet tertiary links/actions use lower visual weight while retaining native buttons and 44px hit areas. Group actions with 8–12px gaps and distinct wrapping. No adjoining buttons without spacing. Disabled remains discernible and truthful, never visually identical to working primary actions. Fields use16px text/12–14px padding. Preserve label association, max lengths, errors and disabled conditions.
7. **Material.** White work surfaces have 14–16px corners and `#DCE1EB` decorative separators; important control edges stay solid/high contrast. Clay is limited to existing small World/agent identity illustrations and Incubator role cards, with existing restrained shadow. No clay bubbles, sculpted forms, hero artwork, new mascots or animated status dots.

### Chat: make the normal work surface convincing

Target markup classes: `chat-view`, `conversation-history`, `conversation-thread`, `conversation-header`, `message-list`, `composer`, `composer-tools`, `conversation-actions`. Apply them around existing JSX, not through new models.

- At desktop, `chat-layout` is `190px minmax(0,1fr)` within the content pane. History gets a subtle right separator, 12px internal gap, prominent **New chat** action and quiet text rows; selected conversation has written/current styling. History titles are left-aligned, normally at most two displayed lines with their full text retained as the button accessible name; do not give one long conversation a giant centered card. Thread max760px centered with 24px side space. This secondary history rail exists only in Chat, not across other surfaces.
- Thread uses a vertical flex layout with a desktop minimum height around `calc(100dvh - 200px)` (not a fixed height). Header is at top; message/work content consumes the middle; the contained composer sits lower via `margin-top:auto` and 24px separation. Keep linked selected work/setup before the composer in document flow where practical, preserving controlled refs/handlers. When content grows, the page expands and scrolls normally; nothing overlays or traps the review. On narrow/zoomed layouts, remove the viewport minimum and keep normal flow. Empty thread has one title and open breathing room, then the lower composer capped at760px. Avoid duplicate “Chat / New chat” headings. No welcome content. Preserve the visible textarea label/Enter-newline rule and small factual mention/send helper.
- Composer is one white 18px rounded container, `#788398` edge, 16px padding. Inside textarea is visually integrated with no second boxed border, minimum96–120px, still resizable; keep local focus indication and visible label. Mention control/chips live in the tools row; **Send** is the rightmost primary. Save draft is secondary, aligned in a separate compact actions row as necessary; keep its function and dirty/conflict guards. At narrow sizes wrap naturally.
- Messages use spacious unboxed vertical rhythm, readable16px prose, a small author/time line and a restrained periwinkle human-message bubble of max90% thread width. No invented assistant replies: current human-only messages remain human-only. Task proposals are a clearly separate linked work card beneath the relevant request/selection. Records/IDs remain in existing Details disclosures.
- Mention picker and task setup stay native labeled select fields with clear panel grouping. All three deliberate participant choices remain required. Do not simplify this into auto-assignment. **Set up an offline task** may be a quieter secondary action; truthfully retain the fixture-only capability warning when setup is open.

### Work and review: organise the existing controls

In `TaskView`, group title/state plus **Open work** as header; show only a compact **Offline example · fictional output** label up front, with exact configuration/input/fixture facts still inspectable in Details. Plain-language state display may map known states in the view; do not alter stored state or conceal failed/unknown results. In Work, a contextual self-link can remain quiet; no routing rewrite is needed.

Each original contribution becomes an attribution header/disclosure followed by a prose panel. The review title/body fields share a clear **Your review copy** section, not an extra generic card nested in every container. Save review copy is secondary; Review and save to Knowledge is primary and obeys existing dirty/conflict/accepted disabling. Confirmation gets its own explicit heading, target/consequence copy, preview and separated Save/Keep reviewing actions. Do not convert confirmation into autosave or merge commands.

### Knowledge: repair the supplied screenshot directly

Use `knowledge-layout` grid `240px minmax(0,1fr)` on desktop. Library column: **Documents**, title rows with short version metadata, selection indicated by text/border, ordinary controls styled as rows. Reading panel:24–32px padding, title24px, compact **Saved · read-only · version1** metadata and one offline-fixture qualifier. If no document is selected, show a short neutral instruction; no fabricated selection/storage. Existing no-documents/error states remain distinct.

Body prose max70ch,16px/1.75. **Remove default code-like rendering without changing text:** style prose-bearing `<pre>` with `font:inherit; white-space:pre-wrap; overflow-wrap:anywhere; margin:0; line-height:1.75`, or replace with safe text-only elements using the same preservation styles. Use this treatment for saved document body, original contributions, review-conflict copy, instructions and confirmation preview. Preserve exact line breaks/content; do not parse agent text as HTML, infer markdown headings or rewrite saved bodies. Reserve monospace only for actual technical identifiers inside Details.

Contributors become a compact wrapping labeled row/list rather than three paragraphs consuming full vertical lines. Keep full agent name/version/assignment inspectable. Footer divider plus grouped **Open source work** and **Open linked Activity** actions. The existing planning-note disclosure goes below the library/read panel with24px separation; it retains actual editor Save and conflict/recovery. Do not fold the note into the saved document or change resource identities.

### Cohesion in remaining surfaces

Activity uses narrow content measure, timestamp and author secondary, event title primary, 20–24px vertical spacing, thin separators and quiet action groups. Display known event names as plain language if mapped locally; unknown names remain visible fallback, not silently omitted.

Incubator keeps all real controls/tree/selection/inspector and source truth. Actual screenshot shows a1868px-tall page caused partly by340px purpose/instructions minima and bold field-value inheritance. Set `.agent-inspector input,.agent-inspector textarea,.agent-inspector select {font-size:16px;font-weight:400;line-height:1.55}`; label weight600 separately. Purpose textarea minimum96px, instructions minimum160px, both vertically resizable with no restrictive maximum. Keep saved body lengths and limits unchanged. Inspector380px on roomy desktop; at available width below1100px stack it rather than narrowing fields. No equal-height/stretching team panel to match a tall form: align grid items at start. Group name/role, purpose/instructions and status/save controls with16–24px gaps; retain truthful configuration-only notice once visibly and exact limitations inspectably. Agent cards use white/near-white surfaces with pastel identity band/emblem, rather than full saturation on every large card; selected has cobalt border + Selected text. Reduce cards to content-driven minimum around150px, identity figure32–36px and restrained local depth. Tree/list/form controls remain real, source labels/version truth intact, no aggressive truncation of role/purpose meaning. Match button/input/spacing/title rules above. Selectors/layout adapt without clipping long labels. World create/details and existing note receive the same form styling, preserving validation, recovery and save controls.

## Adaptation, access and acceptance

At ≤1100px Knowledge list stacks above reading panel; selected document remains current. At ≤900px Chat history becomes a wrapping/list region above thread. At ≤800px shell becomes one column, World control above wrapped five labeled destinations,16px gutters; no accordion/hidden mobile navigation needed. At320/360px actions wrap/stack, inputs/selects remain full width, no fixed panels or horizontal prose overflow. Avoid fixed-height page/sticky bottom composer in this repair: ordinary document flow keeps expanded setup, errors and focus reachable at zoom.

Keep visible 3px cobalt focus with offset; approved token pair white/cobalt6.52:1. No focus interception, remount-driven draft loss or new global keyboard handling. Preserve current keyboard save, enter-newline, dirty navigation dialog and return-focus behaviour. Reduced motion/forced-colour rules remain; meaningful boundaries/selection must survive forced colours. Status announcements, disabled states, semantic headings and native field labels must remain accessible. No CSS `order` that changes semantic reading/keyboard order.
